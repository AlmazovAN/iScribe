## 1. Что должно получиться с точки зрения пользователя

### 1.1. Модели и кнопки

| Блок | Кнопка до загрузки | После подтверждённой загрузки в кеш | Запуск |
|---|---|---|---|
| Whisper Tiny | «Скачать Tiny» | «Выбрать Tiny» / «Загружена» | Распознавание русской речи |
| Whisper Small | «Скачать Small» | «Выбрать Small» / «Загружена» | Распознавание русской речи; выбор по умолчанию |
| Whisper Large v3 | «Скачать Large v3» | «Выбрать Large v3» / «Загружена», если проверка прошла | На слабом устройстве может быть недоступна; предупреждать до загрузки |
| Модели говорящих | **Одна кнопка** «Скачать модели говорящих» | «Модели говорящих загружены» только при подтверждении готовности двух комплектов | При включённой диаризации использовать обе модели |

**Скачано ≠ активно ≠ проверено на аудио.**
- **Скачано:** необходимые веса и сопутствующие файлы доступны в кеше браузера; не считать кеш вечным и не делать ложных выводов из локального UI-флага.
- **Активно:** конкретная Whisper-модель действительно инициализирована в работающем worker. При переключении освобождать предыдущие тяжёлые сессии и только затем активировать новую модель.
- **Проверено:** настоящая запись распознана; текст и временные метки выданы без ошибки. Для диаризации дополнительно получены speaker labels.

Обе модели диаризации скачиваются **вместе одним нажатием**, выбор между ними не предлагается. Технически это два самостоятельных ONNX-комплекта; они оба необходимы. Разумный порядок — сначала загрузка в кеш, затем инициализация/проверка с контролем памяти. Не держать одновременно все модели Whisper + диаризацию в RAM.

При запуске транскрипции, если нужный комплект отсутствует в кеше, приложение должно ясно предложить скачивание/догрузку. Нельзя незаметно начать много-гигабайтное скачивание, особенно Large v3. Если пользователь отключил диаризацию, модели говорящих не обязательны для обычного TXT.

### 1.2. Сценарий использования

1. Открыть опубликованный iScribe по HTTPS.
2. Выбрать Tiny, Small либо Large v3; нажать «Скачать» для нужной модели и дождаться прогресса; ранее скачанную модель можно выбрать без повторного получения весов, если кеш сохранился.
3. Один раз нажать «Скачать модели говорящих» — загружаются **Pyannote + WeSpeaker**. Этот блок не имеет переключателя модели.
4. Выбрать или перетащить локальный WAV/MP3; M4A/OGG — если браузер действительно декодирует файл.
5. Настройки «Разделять говорящих» и «Временные метки» первоначально включены. Пользователь может отключить их.
6. Нажать «Начать обработку»: видеть настоящие стадии декодирования, инициализации, ASR и диаризации, фактический backend (WebGPU/WebNN/WASM) и ошибки.
7. Увидеть предпросмотр; скачать TXT в согласованном формате.

**Аудио не отправляется на сервер распознавания.** Сеть используется для получения приложения и модельных файлов, пользовательская запись остаётся локальной.

### 1.3. Пример контрактного TXT

```text
[00:05] [SPEAKER_00]: Угу.
[05:09] [SPEAKER_00]: Продолжение следует...
[10:06] [SPEAKER_01]: Саша, я сейчас вернусь.
[10:09] [SPEAKER_00]: Угу.
```

- ID определяются по **порядку первого появления**: `SPEAKER_00`, `SPEAKER_01` и т. д.; не подгонять под пример.
- `[MM:SS]` до часа; `[HH:MM:SS]` начиная с часа. Время от начала **оригинального** аудиофайла.
- Метки **по ASR-сегментам**, не гарантированно пословные. Границу смены говорящего внутри сегмента не угадывать.
- При неопределённом говорящем `SPEAKER_UNKNOWN` и предупреждение. Если диаризация запрошена, но метки отсутствуют — результат **частичный**, а не успешная диаризация.
- Если настройка временных меток отключена, не вставлять `[MM:SS]`; если диаризация отключена, не выдумывать speaker ID.
- TXT в UTF-8; проверить кириллицу в Windows/Блокноте; при необходимости добавить BOM.

## 2. Архитектура и технические решения

| Слой | Решение |
|---|---|
| UI | Vite + React + TypeScript strict; русский интерфейс |
| ML | Исходная база — `@yourdevice/engine` **0.1.1**, точная фиксация в lockfile; при необходимости изолированный локальный патч/форк |
| Whisper | Три публичных модели **Tiny / Small / Large v3**, никакой Base или Turbo как видимого варианта на этапе 1 |
| ASR | `language: 'ru'`, `task: 'transcribe'` |
| Спикеры | `onnx-community/pyannote-segmentation-3.0` + `onnx-community/wespeaker-voxceleb-resnet34-LM` |
| Звук | `File` → `AudioContext.decodeAudioData` → 16 кГц mono `Float32Array` |
| Выполнение | Web Worker, WebGPU/WebNN при успешном реальном init, WASM как запасной путь, если работает |
| Кеш | Браузерные механизмы кеширования; отсутствие гарантий бессрочного хранения; честная проверка повторного использования |
| Экспорт | Собственный чистый formatter `formatTranscript.ts`, скачивание TXT |
| Публикация | Статический HTTPS-сайт, без backend inference |

### 2.1. Почему понадобится модификация движка

**Подтверждено по исходникам** `@yourdevice/engine` 0.1.1:

1. В публичном `ModelId` присутствуют `whisper-tiny`, `whisper-base`, `whisper-small` и английская Distil Small. **Large v3 не объявлена**.
2. `EngineClient.init(modelId)` обеспечивает инициализацию Whisper с загрузкой моделей и backend fallback.
3. Диаризация `diarize: true` поддерживается и запускает Pyannote + WeSpeaker, но **отдельного публичного `preloadDiarization()` нет**.
4. Диаризация в upstream best-effort: ошибка может приводить к возврату текста без говорящих.
5. Встроенный `toTxt()` не добавляет требуемые временные метки.
6. Whisper освобождается перед запуском диаризации; этот принцип необходимо сохранить на машинах с 8 ГБ RAM.

**Решение:** в начале проекта сделать техническую проверку расширяемости движка для двух нужных API: `prepareWhisper('whisper-large-v3')` и `preloadDiarizationModels()`. Имена здесь описательные, а не существующие upstream API. Не выдавать их за готовые функции.

Предпочтительно: небольшой собственный адаптер и точечный патч/форк **внутри iScribe**, без изменения чужого GitHub-репозитория. Если расширение нужно, его версии, дифф, лицензии и обновления должны быть воспроизводимы. Не копировать большие куски закрытого EarScribe; не превращать весь проект в самостоятельный ML-фреймворк.

### 2.2. Отдельный риск: Whisper Large v3

**Large v3 — не Large v3 Turbo.** У `onnx-community/whisper-large-v3-ONNX` есть различные варианты ONNX весов, включая fp16 и q4. Например, в опубликованном репозитории fp16-encoder ≈1,27 ГБ, merged q4-decoder ≈797 МБ; это **размеры файлов отдельных вариантов**, а не обещанный размер конкретной рабочей конфигурации и не оценка использования RAM. Сумма выбранных компонентов может превышать 2 ГБ, а в памяти выполнение потребует больше.

Ссылка: https://huggingface.co/onnx-community/whisper-large-v3-ONNX/tree/main/onnx

На ноутбуке Ryzen 5 5500U / Radeon iGPU / 8 ГБ ОЗУ запуск Large v3 **не подтверждён и потенциально непрактичен**. Не нужно выдавать наличие ONNX-весов за доказательство успешной расшифровки. Обязателен контроль загрузки памяти/времени, и понятное предупреждение пользователю. Возможно понадобятся специфические варианты квантизации или отдельная ветка исполнения.

**Релизное правило:** Tiny/Small-распознавание не должно зависеть от успеха Large v3. Если Large v3 не удаётся достоверно запустить, оставить её статус `NOT TESTED`/`UNSUPPORTED ON THIS DEVICE`, а не показывать работающей; честно указать, что требование полной тройки моделей ещё не принято. Не заменять её Turbo по собственной инициативе.

### 2.3. Ещё один аппаратный риск

В upstream Transformers.js сообщалось о росте GPU-памяти при длительной Whisper-обработке; зафиксировать версии зависимостей и проверять длинные записи, повторные транскрипции, освобождение ресурсов и стабильность браузера. Документированный инцидент: https://github.com/huggingface/transformers.js/issues/1739

## 5. Требования к запуску, памяти и кешу

1. Не устанавливать Python, PyTorch, FFmpeg или Node.js на ПК обычного пользователя. Для сборки проекта Node.js/npm допустимы; для использования опубликованного HTTPS-сайта — нет.
2. При переключении Tiny ↔ Small ↔ Large v3 **не держать одновременно** три inference-графа. Кешированные файлы остаются по возможности, сессии/Worker освобождаются.
3. Диаризация выполняется после ASR, в память не нужно одновременно загружать все графы; соблюдать upstream-логику освобождения Whisper до Pyannote+WeSpeaker.
4. Кеш браузера может быть очищен системой; повторная загрузка допустима. Статус «в кеше» подтверждать данными runtime/кеша, не только localStorage или реактовским состоянием.
5. Загрузка/декодирование длинного аудио может давать большой расход RAM ещё до inference. Проверить ограничения и предусмотреть понятные ошибки.
6. Закрытие/перезагрузка вкладки прерывает обработку. Не обещать работу после закрытия сайта или выключения ноутбука.
7. Не хранить аудио, текст и токены в удалённых логах. Не отправлять пользовательскую запись на сервер. Проверить сетевой трафик.
8. Скачивание моделей — из сети, сами ONNX-файлы не коммитить. При смене версий обеспечивать контроль совместимости и лицензий.
9. «Временные метки» на уровне сегментов. Не обещать точность пословного WhisperX alignment.
10. Если Large v3 на конкретном устройстве не поддерживается, показывать честную причину/рекомендацию выбрать Small/Tiny, не переключать автоматически и незаметно.

## 6. Реальные испытания и release gate

| Gate | Входные данные/условие | Критерий |
|---|---|---|
| **A — русская речь** | WAV/MP3 20–60 секунд, один говорящий | Настоящий текст с сегментами и правильным языком, без сервера |
| **B — говорящие** | WAV/MP3 1–3 минуты, два голоса, несколько смен | Две устойчивые группы speaker ID; если speaker labels не пришли — частичный результат, не PASS |
| **C — короткие реплики** | «Угу», «Да», перебивания | Задокументировать ограничения и ложные объединения |
| **D — кеш** | Первый/повторный запуск Tiny/Small, затем двух моделей диаризации | Веса реально скачаны и кешированы, повторно используются при наличии кеша |
| **L — Large v3** | Настоящая русская запись, подходящий браузер/железо | Подтверждено скачивание, инициализация, ASR и время; без такого испытания — NOT TESTED |
| **E — TXT** | Кириллица, 1+ час, сегменты, два спикера, неизвестный спикер | Совпадение формата и открытие файла Windows |
| **F — приватность** | DevTools Network при обработке записи | Нет upload пользовательского аудио и нет стороннего ASR API |
| **G — устройство пользователя** | Windows 11, Ryzen 5 5500U, встроенная AMD Radeon, 8 ГБ, Chrome/Edge/Opera | Замер RAM, времени, стабильности, WebGPU/WASM и диаризации; только на реальном устройстве |

**Статусы:** `PASS`, `FAIL`, `NOT TESTED`, `UNSUPPORTED`. Сборка/CI PASS не заменяет inference PASS. Если реальные B/G/L не выполнены, допускается только техническая интеграция с честным списком неподтверждённых требований, не утверждение «полный MVP принят».
