## Policy and rollout

Full PCM, eligible PIPE-04 checkpoint jobs only: opt in via ?vad=silero&segmentation=adaptive. Default remains fixed windows (30 seconds, step 25 seconds). Long/windowed PCM and jobs without a compatible checkpoint service use baseline. VAD remains experimental; no speech removal or time compression is enabled. If the VAD is unavailable or has no suitable pause, use baseline; valid empty maps cannot cause silence-only audio to be skipped. Adaptive planning must not reinterpret a previously committed window or an outstanding ASR reservation. Existing jobs with any prior ASR progress or reservation continue their fixed plan. Once an adaptive plan is durably published, its precise geometry is used on every explicit resume, even with both experimental flags absent; the VAD is skipped because the plan is pinned.

## Window geometry

- All coordinates are integer source samples at 16 kHz, half-open PCM intervals. Input fully covered, first starts at 0, last ends at original sample count.
- Maximum Whisper window is 480000 samples (30 s). Adjacent windows overlap exactly 80000 samples (5 s), unchanged from baseline. Nominal ownership boundary is 40000 samples before a nonfinal window end.
- Candidate cuts are sought within 80000 samples (5 s) BEFORE nominal boundary. Use the latest feasible point in the complement of the padded VAD intervals, at least 4000 samples (250 ms) from either pause edge. Estimated pauses must be at least 8000 samples. If none, retain nominal boundary. Nonfinal windows are 25–30 s and advance 20–25 s. Last window can be shorter. A map with no actual boundary changes keeps the fixed plan.
- Midpoint ownership from absoluteSegments is preserved because overlap is still exactly 5 s; an identical segment midpoint on a boundary belongs only to the later window. ASR predictions across overlapping windows can differ: this is not proof of zero transcript duplicates or missing words. No modification of timestamp tolerance or model inference in this stage. Real text quality must be measured.

Example for 60 s source, padded VAD speech [0,24] and [26.5,60]: fixed windows [0,30], [25,55], [50,60]; adaptive windows [0,28.75], [23.75,53.75], [48.75,60]. The first ownership cut is moved from 27.5 to 26.25 s. Original audio and every absolute offset remain available.

## Persistence and compatibility

SpeechWindowPlan revision 1 / pause-aware-v1 is optional metadata in existing IndexedDB v3; no schema migration. For an adjusted plan publish immutable window list, sample count, exact full PCM fingerprint (PIPE-04 bounded SHA-256-of-chunks), decoder profile, adjusted cut count, algorithm revision. Use the existing JobStore transaction before model initialization, before ASR reservation and before dispatch. Plan creation requires nextWindow=0 and no ASR ledger record. Guard at JobStore rejects removal or alteration, corrupted bounds/count/fingerprint format, new plan after progress/reservation and invalid ASR completion count. The plan is structurally validated and matched against actual decoded PCM/profile on resume, not cryptographically authenticated against deliberate modification of all metadata. Source identity remains checked by PIPE-04. Failed plan persistence stops before ASR; no unsafe baseline switch after publication. Missing or incompatible PCM/checkpoint service stops a pinned job; preserve prior text and create a fresh job after investigation. Raw ASR key includes segmentation contract only for adaptive jobs; fixed keys unchanged.

JobRow, diagnostic report, failure diagnostic, DiagnosticsPanel and hardware evidence now use actual plan counts and committed end positions. Existing progress semantics count the end of the last processed window including overlap, not ownership end. Benchmark uniqueAudioSeconds keeps exact incremental coverage. Hardware baseline gate for 14:31 / 35 fixed windows does not accept adaptive plan as the same reference. Diagnostic trace exports mode, adjusted cuts and window count, not the PCM fingerprint or whole VAD map. Full plan is local job metadata. No changes to recovery limits or database version.
