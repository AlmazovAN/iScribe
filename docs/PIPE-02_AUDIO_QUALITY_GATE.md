## Scope
Extend current src/audioValidation.ts rather than introducing a competing validator. Production JobRunner still invokes FFmpeg directly via the existing decoder provider, accepts Float32 mono PCM at 16 kHz, and validates before dispatch to ASR. The full route validates before Whisper initialization; stream validates every requested window before inference (model initialization may precede the first stream check). Includes normal, split-recovery, prefetched and manual window inspection. No new decoder, VAD, model, dependency, DB migration, changes to retry budgets or PCM normalization. ## Contract and decision
- Hard failures (existing): empty/wrong type/oversized/nonfinite PCM, wrong window plan, missing samples in a requested window. Now the shared gate can additionally check exact expected coverage and absolute sample coordinates. Retain the existing FFmpeg sample-count check against saved ASR checkpoints; reject invalid stream data without repeating inference or advancing a checkpoint. Adapter-level FFmpeg finite validation reports the absolute sample index. Full report duration = sample count / 16000, not an independent measurement of correct sampling rate.
- New diagnostic-only signal metrics: RMS, DC offset, number of exactly zero samples, longest exact-zero run, near-full-scale count (abs >= 0.999), out-of-range count (abs > 1), largest adjacent-sample step, absolute half-open interval [startSample,endSample). Existing peak and quiet/near-clipped window counts preserved. Silence, quiet speech, clipping and finite values outside [-1,1] are not themselves a reason to block or alter audio. These indicators do not prove damaged compressed frames, missing speech or a timestamp discontinuity; do not infer VAD from them. No automated trim, padding, gain change or removal.
- Within one full PCM report count source samples once, even across 5s ASR overlap. Within one stream report count only the given window; distinct reports overlap and must not be summed as unique whole-recording statistics. Existing aggregate streamed inspection retains old counters and intentionally does not claim whole-file RMS/zero-run. Boundary jumps between separately decoded windows are not independently validated by this metric.
- Trace event audio-ready optionally records durationDeltaSamples vs previously observed job duration. Before first decode the prior duration may come from browser/container metadata and is advisory, not a blocking threshold. Exact FFmpeg resume-length protection remains unchanged. No source SHA-256 yet: byte-level identity and reusable stage checkpoints belong to PIPE-04. No new assertion about actual sample-rate provenance or audio track beyond current adapter contract.
- On validation failure publish only closed reason and numeric absolute sample/window where available. On pass retain versioned numeric quality summary in existing full audioCheck and per-window trace; speculative prefetch publishes evidence only when consumed. No raw PCM, source filename, paths or exceptions in JSON. Legacy reports without optional quality fields remain readable. Existing trace cap and transaction semantics retained.
- Existing duplicate scan at decoder adapter + runner retained, no extra PCM copy or extra decode. Added arithmetic is within existing scan; actual cost must be benchmarked (PERF). Cancellation after final progress callback now rejects rather than returns a successful report.
