# PERF-03 — Backend Optimization

Opt-in comparison under Diagnostics: arm next ASR run. Same first uncommitted PCM fragment (up to 15 s) for actual baseline and exposed WebGPU/WebNN/WASM candidates, max three candidates. Each candidate gets a strict provider request, initialization, one warm-up and two timed passes; each stage has a 120 s foreground budget. No parallel model sessions, no calibration transcript appended to checkpoints, no extra ASR retry budget. Empty or differing normalized text is rejected; a candidate must beat baseline by >10%. A single local sample is not a WER test. Existing provider-specific dtype and model settings remain unchanged; different providers may use different engine dtypes. Additional model files may be downloaded only as part of explicit comparison or existing engine behavior.

Cache choice only after at least two matching provider results; model/language/build key, seven-day expiry, no adapter IDs, no persistent cache if build unavailable. Medium/max use cached choice at start of job; eco retains original engine policy because speed does not establish energy use. On cached initialization failure invalidate choice and return once to original auto policy, except cancellation or explicit resource exhaustion. Existing ASR recovery retains WASM-only fallback and invalidates a failing selected backend. During calibration a failed alternative is not repeated; explicit resource exhaustion stops the job, preserving prior checkpoints. No automatic benchmarking on every job. On restore failure stop rather than loop. Switching performance mid-job does not replace the backend: only pacing changes at window boundaries.

Backend observations include requested WebGPU/WebNN/WASM vs actual. Benchmark JSON contains only numeric timings and fixed status labels, no transcript or raw error. Direct adapter preference, GPU buffer residency, actual power and transfer measurements remain unimplemented; engine/provider internals and real-device validation are needed. No quality/speed claims before PERF-09.

Tests added for strict backend verification, candidate choice, expiry and invalidation. Full CI and hardware status NOT TESTED until observed.
