# iScribe

Проверочная версия локальной расшифровки русской речи в браузере.
**Сборка и тесты не подтверждают реальное распознавание.** Gate A/B/L/G пока NOT TESTED.

## Пользование в Windows

1. Откройте опубликованный HTTPS-сайт в актуальном Chrome, Edge или Opera.
2. Скачайте Whisper Tiny или Small. Для первого теста отключите разделение говорящих.
3. Добавьте одну или несколько аудиозаписей и нажмите «Начать» в строке файла.
4. TXT и TXT + time доступны по мере получения текста, в том числе во время обработки спикеров.
5. После диаризации доступен TXT + time + speaker. Частичный результат обозначается явно.
6. После перезагрузки нажмите «Продолжить» или «Повторить спикеров»: сохранённые фрагменты текста не распознаются заново.

Python, Node.js, FFmpeg и локальный сервер пользователю не нужны. Аудио и текст
хранятся в браузере на устройстве, без отправки на ASR-сервер. Не очищайте данные
сайта до скачивания результатов. Вычисления при перезагрузке прекращаются;
восстанавливается сохранённая работа. Подробности и ограничения —
[сохранение, очередь и приёмка](docs/RELIABILITY_RELEASE.md).

## Модели и ограничения

Ровно три варианта: Tiny, Small (по умолчанию), **полная Large v3**, без Turbo.
Large v3 экспериментальная: загрузка нескольких ГБ и высокий расход RAM;
возможны отказ и закрытие вкладки. Запуск требует предупреждения-подтверждения.
На каждой карточке Whisper видны статус, общий полученный объём известных файлов, подготовка и подтверждение кэша. Неизвестный полный объём не подменяется процентами отдельного файла. «Скачана» означает подтверждённый комплект файлов, а «Готова к работе» — успешную инициализацию. Ошибка и отмена отображаются на той же карточке.
Кеш не вечен; статус готовности проверяется через Cache API, не localStorage.
Диаризация — обе модели Pyannote + WeSpeaker, профиль q8/WASM; ASR имеет
upstream fallback WebNN → WebGPU → WASM. Backend показывается после init.
Одновременно загружается одна Whisper-сессия. Перед диаризацией она освобождается.

Файл до 500 МиБ. Для файлов до 128 МиБ действуют ограничения обычного режима: до одного часа и до 256 МиБ декодированного PCM. Файлы свыше 128 МиБ декодируются по 30-секундным окнам с 5-секундным перекрытием, в том числе для записей дольше часа. В потоковом режиме доступны TXT и TXT с таймкодами. Общая разметка спикеров пока доступна только в обычном режиме. Для больших записей нужен браузер, способный декодировать выбранный аудиокодек.
Browser decode может временно потреблять больше памяти ещё до проверки длительности.
Форматы кроме MP3/WAV зависят от браузера. Не закрывайте вкладку; фоновая работа
и длинные файлы не проверены. Постоянное офлайн-хранение не обещается.
Если меток говорящих нет, результат частичный, в TXT со спикерами — SPEAKER_UNKNOWN. Обычный текст остаётся полным результатом распознавания.
TXT: время исходной записи, метки по сегментам, UTF-8 BOM, CRLF.

## Разработка

Node.js 22+ и npm. Установка нативного onnxruntime-node не требуется:
`.npmrc` отключает lifecycle scripts для browser-only сборки.

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run release:check
npm run dev
```

`prepare:engine` явно выполняется перед dev/typecheck/test/build. Он проверяет
версию engine 0.1.1 и SHA-256 исходных/изменённых файлов перед узкими патчами.
Обновление зависимости требует пересмотра патчей. Не отключайте проверки хешей.
Зафиксированные версии — в package-lock.json; веса в git не хранятся.

`npm run build` собирает **`dist/iScribe.html`**. JavaScript, CSS, worker,
ONNX/WASM и лицензии встроены. HTML можно открыть напрямую в Chrome или Edge
или по адресу `/iScribe.html` на локальном сервере. Веса Whisper, Pyannote и
WeSpeaker загружаются при первом использовании и сохраняются в кэше браузера.
Проверка доступности кэша зависит от браузера и адреса открытия файла.

Основной цикл разработки проходит локально на ноутбуке: проверки TypeScript, ESLint, Vitest и Playwright, затем сборка.
GitHub Actions выполняет те же проверки и финальную сборку в `dist/` на runner. CI не загружает результат сборки и отчёты тестов в артефакты.

## Очередь распознавания

Активные задания идут сверху в порядке очереди с номерами. Завершённые записи находятся внизу. Корзина снимает ожидающую запись с очереди или запрашивает остановку текущей, сохраняя исходник и уже полученный текст. Корзина вне очереди открывает подтверждение удаления записи.

Над шкалой видны текущее окно Whisper, сохранённый прогресс таймкодов и прогресс разметки говорящих. Во время работы шкала переливается.

Кнопка скачивания комплекта Pyannote + WeSpeaker принимает запрос во время распознавания. Загрузка начнётся после текущей записи, перед следующей.

## Диагностика

Раздел под строкой состояния ML объединяет аппаратную приёмку, проверку автономной работы и инструменты выбранной записи. В журнале видны последние события, окно, попытка, backend и тип ошибки. Журнал и бенчмарк можно скачать в JSON.

## Прототип Google Drive / Colab

Откройте «Google Drive / Colab» в верхней панели. Можно вставить ссылку на файл Drive, выбрать локальный файл или запустить один из демонстрационных сценариев. Очередь, контрольные точки и события сохраняются в браузере. Обработка и готовый TXT демонстрационные.

## Подготовка релиза PR-31

Компактные карточки моделей и файлов оставляют главные действия — запуск и три формата TXT — видимыми. Проверка аудио, диагностика и бенчмарк доступны в меню «Дополнительно»; длинные показатели раскрываются через «Подробности обработки». Внизу страницы отображается короткий SHA собранной версии и предупреждение «Тестовая сборка».

После сборки используйте `npm run release:check` для проверки монолитного файла. Для версии сайта используйте `npm run release:check:web`. Это проверка файлов пакета, **не** полноценное испытание Whisper. Перед публикацией см. [план PR-31](docs/PR31_UI_RELEASE_PREP.md), включая порядок PR-21–31, миграцию IndexedDB и ручные аппаратные испытания.

## Публикация

`npm run build:web` собирает `dist-web/` с Service Worker для GitHub Pages.
Этот пакет с относительными URL ресурсов пригоден для размещения
в корне или `/iScribe/`. Итоговый адрес и статус публикации — в
[docs/HANDOFF_STAGE_1.md](docs/HANDOFF_STAGE_1.md).

Для самостоятельной публикации на GitHub Pages: Settings → Pages → Source:
GitHub Actions. Затем Actions → «Deploy Pages (manual after Pages enablement)»
→ Run workflow. Workflow намеренно ручной: включение Pages требует настроек
владельца и может быть недоступно через текущий GitHub connector.

## Аппаратная приёмка

На странице есть сворачиваемый раздел **«Аппаратная приёмка · Не подтверждена»** и кнопка **«Скачать протокол наблюдений JSON»**. Протокол сверяет текущую запись с данными IndexedDB и не содержит исходное аудио, его имя или текст. Он **не** подтверждает подлинность работы Whisper, видеокарты или точность меток говорящих. Контрольные испытания HW-1–HW-7 необходимо выполнить на реальном устройстве по [плану PR-30](docs/PR30_HARDWARE_ACCEPTANCE.md). Синтетический CI не считается аппаратной приёмкой.

## PR-18 — браузерные тесты приёмки

Отдельная suite Playwright открывает настоящую страницу React через Chromium и проверяет IndexedDB, Cache API, перезагрузку, 35 окон (14:31) и три скачанных TXT. В ней **используется имитация Whisper/декодирования**, без реальных весов и GPU; это не доказательство качества реального распознавания.

Для локального запуска после `npm ci`: `npm install --no-save --package-lock=false @playwright/test@1.56.1`, `npx playwright install chromium`, `npx playwright test`. Отдельный job `browser-acceptance` запускается в CI. [Приёмочные сценарии с настоящим аудио](docs/PR18_BROWSER_ACCEPTANCE.md) требуют реального браузера и файла и пока имеют статус NOT TESTED.
