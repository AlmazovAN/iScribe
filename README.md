# iScribe

Проверочная версия локальной расшифровки русской речи в браузере.
**Сборка и тесты не подтверждают реальное распознавание.** Gate A/B/L/G пока NOT TESTED.

## Пользование в Windows

1. Откройте опубликованный HTTPS-сайт в актуальном Chrome, Edge или Opera.
2. Для первого теста отключите «Разделять говорящих» и нажмите «Скачать Tiny».
3. Дождитесь успешной инициализации. В «Состояние» появится фактический backend.
4. Выберите MP3/WAV с русской речью, лучше 20–60 секунд. При желании нажмите «Проверить аудио».
5. Нажмите «Начать обработку», проверьте текст и нажмите «Скачать TXT».
6. Для разделения голосов нажмите «Скачать модели говорящих», дождитесь подтверждения обоих комплектов, затем **снова выберите Whisper**, включите разделение и повторите обработку.

Python, Node.js, FFmpeg и локальный сервер пользователю не нужны.
Аудио обрабатывается в Worker на устройстве. Сеть используется для приложения,
модельных файлов и служебных запросов загрузчика; аудио и текст не отправляются
на ASR-сервер. Сетевой privacy-gate в браузере ещё не проведён.

## Модели и ограничения

Ровно три варианта: Tiny, Small (по умолчанию), **полная Large v3**, без Turbo.
Large v3 экспериментальная: загрузка нескольких ГБ и высокий расход RAM;
возможны отказ и закрытие вкладки. Запуск требует предупреждения-подтверждения.
На каждой карточке Whisper отдельно видны статус скачивания, прогресс в процентах и МБ/ГБ, подготовка модели и подтверждение сохранения. «Скачана» означает подтверждённый комплект файлов, а «Готова к работе» — успешную инициализацию. Ошибка и отмена отображаются на той же карточке.
Кеш не вечен; статус готовности проверяется через Cache API, не localStorage.
Диаризация — обе модели Pyannote + WeSpeaker, профиль q8/WASM; ASR имеет
upstream fallback WebNN → WebGPU → WASM. Backend показывается после init.
Одновременно загружается одна Whisper-сессия. Перед диаризацией она освобождается.

Лимиты этого выпуска: файл до 128 МБ, до 1 часа, до 256 МБ декодированных каналов.
Browser decode может временно потреблять больше памяти ещё до проверки длительности.
Форматы кроме MP3/WAV зависят от браузера. Не закрывайте вкладку; фоновая работа
и длинные файлы не проверены. Постоянное офлайн-хранение не обещается.
Если меток говорящих нет, результат частичный, в TXT — SPEAKER_UNKNOWN.
TXT: время исходной записи, метки по сегментам, UTF-8 BOM, CRLF.

## Разработка

Node.js 22+ и npm. Установка нативного onnxruntime-node не требуется:
`.npmrc` отключает lifecycle scripts для browser-only сборки.

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run dev
```

`prepare:engine` явно выполняется перед dev/typecheck/test/build. Он проверяет
версию engine 0.1.1 и SHA-256 исходных/изменённых файлов перед узкими патчами.
Обновление зависимости требует пересмотра патчей. Не отключайте проверки хешей.
Зафиксированные версии — в package-lock.json; веса в git не хранятся.

## Публикация

`dist/` — статический сайт с относительными asset URL, пригодный для размещения
в корне или `/iScribe/`. Итоговый адрес и статус публикации — в
[docs/HANDOFF_STAGE_1.md](docs/HANDOFF_STAGE_1.md).

Для самостоятельной публикации на GitHub Pages: Settings → Pages → Source:
GitHub Actions. Затем Actions → «Deploy Pages (manual after Pages enablement)»
→ Run workflow. Workflow намеренно ручной: включение Pages требует настроек
владельца и может быть недоступно через текущий GitHub connector.

## Проверки и дальнейшая работа

16 unit tests: аудиоданные/валидация, кеш и его утрата, точный Large v3 ID,
защита патча, формат TXT и UTF-8 BOM. Все browser/inference/hardware gates
необходимо выполнить по [передаче этапа](docs/HANDOFF_STAGE_1.md).
Этапы IS-09…IS-19 не выполнялись.
